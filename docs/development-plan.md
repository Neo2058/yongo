## 1. Что это

Сайт разработчика (Yongo). Стек в позиционировании: React, Next.js, Nest.js, PHP, UE5, C++, 3ds Max, Blender, HTML/CSS/JS, Assembler, Linux/Windows, сервер с нуля, Docker, GitHub, работа с агентом Grok.

Три поверхности одной системы:

| Поверхность | Кто видит | Зачем |
|---|---|---|
| Публичная | любой посетитель | услуги, заказ, работы, блог, обо мне, заявка |
| Закрытая | приглашённые руководители | рабочий журнал / брифы, постановка задач владельцу |
| Управление | только владелец | CMS + CRM: контент, услуги, заказы, заявки, доступы |

Приоритет витрины: **продавать услуги**. Кейсы `/work/[slug]`, оплата, Nest и кабинет клиента — не блокируют текущую работу.

### Админка (`/dashboard`)

Вход: `/dashboard/login`. Регистрации нет.

| Раздел | Что делает |
|---|---|
| Обзор | Счётчики услуг, заказов, страниц, блога, журнала, заявок, todo |
| Блог | CRUD `type=article`, канал public |
| Страницы | Правка `/work` и `/about`. Адрес нельзя сменить, удалить нельзя |
| Услуги | CRUD `channel=shop` + `type=service` |
| Журнал | CRUD `channel=internal`. Из todo можно завести запись (`?from=`) |
| Заявки | Воронка + архив. Удаление только из архива |
| Заказы | `new → qualified → in_progress → delivered → closed/cancelled` + архив. Оплаты нет |
| Todo | Задачи от руководителей, архив выполненных |
| Доступ | Инвайты, отзыв до конца доступа (не TTL 7 дней) |

Сессия: httpOnly cookie, хеш токена в БД, scrypt пароля, rate limit на логин. `proxy.ts` — ранний отсев без cookie на `/dashboard*`. Права на каждой операции проверяет DAL (`requireOwner` / `requireBriefingUser`). Менеджер на `/dashboard` получает 404.

### Руководители

- Инвайт в **Доступ**: одноразовая ссылка `/i/[token]` (256 бит). Неверный/погашенный/отозванный → 404.
- Руководитель задаёт пароль, дальше входит на `/gate`.
- `/briefing` — только `owner | manager`, опубликованный `channel=internal`. Нет в публичном меню.
- Из брифинга можно поставить задачу владельцу.
- Комментариев под записью нет. AuditEvent «кто открыл» нет.

### Данные и медиа

- SQLite `data/yongo.sqlite`, схема через `migrate()`. Прод-план — Postgres.
- Владелец из `OWNER_EMAIL` / `OWNER_PASSWORD` **только пока таблица users пустая**.
- Секреты в `.env.local`, не в git.
- Публичные файлы: `/media/public/...`. Журнал: `storage/internal/` → `/media/internal/...` только с сессией.

## 3. Безопасность — не сдвигаем

Скрытый URL **не является защитой**. Закрытый контур — три слоя сразу. Один слой без двух других считается дырой.

```
Слой A — невидимость
  нет пункта в публичном меню
  нет записи в sitemap
  не светить путь в robots.txt (Disallow рекламирует секрет)
  X-Robots-Tag: noindex, nofollow на закрытых ответах
  для постороннего тот же 404, что у несуществующей страницы

Слой B — вход только по приглашению
  токен одноразовый, дальше сессия
  cookie: httpOnly, Secure (на https), SameSite=Lax/Strict

Слой C — проверка на каждой операции
  proxy.ts только рано отсекает «похоже, не залогинен»
  право читать/писать — в DAL на сервере
  Server Action без проверки роли = обход UI
  в клиент уходит только DTO
```

Правило: не знаешь ссылку → не видишь, что подсистема есть. Знаешь, но не приглашён → 404. Приглашён, доступ отозван → 404 или «нет доступа» только после успешного входа.

`robots.ts` сейчас запрещает только `/dashboard`. Пути `/gate`, `/briefing`, `/i/` в robots **не добавляем**.

## 4. Роли

| Роль | Как появляется | Права |
|---|---|---|
| `owner` | единственный аккаунт | весь CMS/CRM, все каналы, инвайты, заказы |

Публичной регистрации нет. Руководитель не приглашает других. Отзыв инвайта отключает пользователя и сессии.

## 6. CMS и CRM

Одна таблица контента, не три блога.

```
Content
  channel:  public | internal | shop
  status:   draft | published | archived
  type:     article | case | service | briefing | page
  featured, kicker, tags, cover, markdown body

Lead          /contact
Order         /services или /order
  status:     new | qualified | in_progress | delivered | closed | cancelled | archived
Invite        токен, email, role=manager, usedAt, revokedAt
              expiresAt = 9999, пока не отозвали
Session
Task          todo от руководителя владельцу
MediaFile     public | internal
```

Правила:

- `public` + `article` + `published` → `/blog`.
- `public` + `page` + slug `work`/`about` → эти маршруты. Не блог.
- `shop` + `service` + `published` → каталог, можно заказать.
- `internal` + `published` → только сессия owner/manager.
- `type=case` заложен, публичного списка кейсов ещё нет.
- Черновик не существует для публики и руководителя.
- Заявка и заказ пишутся в БД. Письмо владельцу — `after()` + SMTP; нет SMTP → лог, запись остаётся.
- Оплата в текущей версии **не входит**.

```
src/

    (site)/            лендинг, services, order, work, about, blog, contact
    (briefing)/        /briefing
    dashboard/         CMS/CRM владельца
    gate/              логин руководителя

    actions/           Server Actions
```

`'use client'` только на листьях (формы, шапка, нав админки). Layout публичной части — Server Component.

Перед кодом на Next 16 — гайды в `node_modules/next/dist/docs/`. В этой версии: `proxy` вместо `middleware`, `params` — Promise, у Image — `preload` не `priority`.

## 8. План дальнейшего развития

Порядок обязательный: не начинаем следующий срез, пока текущий не закрыт проверяемыми фактами. Приоритет задан продуктом: сначала заявки с витрины, потом портфолио-кейсы, потом прод.

### Срез A — довести продающий контур

**Закрыт кодом 2026-09-13.** Письмо после INSERT через `after()`. Нет `SMTP_HOST` → лог `SMTP не настроен`, строка в CRM на месте. Состав услуги — в markdown карточки, без выдуманных цен. Проверка с телефона — на живом VPS.

Шлюз: заказ в `/dashboard/orders`; письмо или лог без потери записи.

### Срез B — кейсы `/work/[slug]`

Цель: работы продают так же, как услуги, не смешиваясь с блогом.

- `type=case`, канал public, список на `/work` под текстом страницы.
- Админка: кейсы отдельно от блога и от страницы `/work`.
- Обложка + разбор + ссылка «заказать похожую».
- Не WebGL по умолчанию: видео/постер.

Шлюз: кейс открывается по `/work/[slug]`, не виден в `/blog`, снят с публикации — 404.

### Срез C — подготовка к своему серверу

**Закрыт кодом 2026-09-13.** Осталось прогнать на VPS.

- `.env.example` без секретов; `.env*` в gitignore, example — нет.
- `yarn lint`, `yarn build`, `output: "standalone"`.
- CSP (nonce в `proxy.ts`), `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'`, `X-Frame-Options`, `Permissions-Policy`.
- `sitemap.ts` только публичное. `robots.ts` Disallow только `/dashboard`.
- `yarn backup` → `data/backups/`. Postgres — смена драйвера Drizzle, не новая CMS.
- Docker + compose, тома `data/` и `storage/`.
- Cookie `Secure` при `NODE_ENV=production`.
- Нейтральный 404, свои `error.tsx` / `global-error.tsx` без `error.message`.

Шлюз: `yarn build` локально; на VPS — заголовки в ответе, аноним `/briefing` и `/i/guess` как обычный 404.

### Срез D — закрытый контур для живой работы с руководителями

- Комментарий под briefing (если понадобится в работе, не «на всякий случай»).
- AuditEvent: кто открыл какую internal-запись.
- Отзыв доступа уже есть — проверить сценарий «отозвал → следующий запрос 404».

Шлюз: отозванный менеджер не читает журнал; в админке видно, кто открывал запись.

### Срез E — когда CRM станет тесной

Не раньше, чем срезы A–C закрыты, и только если Server Actions реально мешают.

- Домен заказов/очередей/писем в Nest.js как внутренний API.
- Next остаётся UI и BFF.
- PHP по-прежнему не рантайм этого сайта.

### Срез F — отдельно, не смешивать с витриной

- Онлайн-оплата (PCI, вебхуки, идемпотентность).
- Кабинет `client`.
- Светлая тема.
- Мультиязык.

## 9. Угрозы на каждом срезе

| Угроза | Где | Как закрываем |
|---|---|---|
| Security through obscurity | скрытый маршрут | §3, три слоя |
| IDOR | `/briefing/[slug]`, админка | DAL, не UI |
| Утечка RSC payload | объект в Client Component | DTO + `server-only` |
| XSS | markdown, заявка в админке | не сырой HTML; свой рендер markdown |
| CSRF | Server Actions | сессия внутри экшена |
| Перебор инвайтов | `/i/[token]` | длинный токен, одинаковый 404, rate limit |
| Спам | `/contact`, `/order` | honeypot, rate limit |
| Open redirect | `?next=` | allowlist |
| Path traversal | медиа | свои имена, internal вне web-root |
| Перечисление пользователей | логин, инвайт | одинаковые ответы |
| Секрет в git | `.env`, `NEXT_PUBLIC_*` | gitignore; публичный префикс = браузер |
| Clickjacking | любая страница | `frame-ancestors 'none'` + `X-Frame-Options: DENY` |
| Индексация закрытого | sitemap/robots/OG | не включать, noindex, 404 анониму |

В `error.tsx` продукта — нейтральный текст, не `error.message` с сервера.

## 10. Тема и анимация

- Тёмная — default. Светлая — отдельный срез.
- Анимация: герой, карточки, состояния форм. Не анимировать админку ради эффекта.
- `prefers-reduced-motion: reduce` отключает движение.
- UE5/Blender в кейсах как видео/постеры, не WebGL на каждую страницу.

## 11. Как ведём проект с Grok

- Перед кодом Next 16 — `node_modules/next/dist/docs/`, не память модели.
- Каждая новая поверхность (форма, id, инвайт, файл) — короткий разбор угроз до реализации.
- Не добавляем библиотеку «на будущее».
- Проверка: сценарий пользователя, не один скрин. Нет браузерных инструментов — HTTP как пользователь и явная оговорка.
- Этот файл обновляем, когда решение меняется.

## 14. Исправления безопасности — 2026-10-08–09

Обновлены Next.js/React и зависимости по результатам npm audit. Принятие/отзыв приглашений и bootstrap владельца защищены транзакциями; неизвестные роли запрещены; инвайт-ссылка живёт 7 дней, уже принятый доступ — до отзыва. Старое решение о бессрочных ссылках в журнале оставлено как история и заменено новым.

Rate limit перенесён в SQLite, IP берётся только от явно доверенного приватного proxy. Проверка публикации распространяется на uploads, кеширование upload-ответов запрещено, public/internal ссылки нельзя смешивать. Исправлены env-исключения Docker, loopback-порт, лимиты загрузки и смена пароля. Бэкап включает БД и файлы; добавлены регрессионные security-тесты, CI и примеры Nginx.

Полный журнал выполненного, результатов проверок и следующих задач: [`production-security.md`](production-security.md). Production не считается готовым до VPS-проверок HTTPS, ролей/RSC/actions, SMTP, внешних backups, восстановления и мониторинга. Исторические утверждения «срез C закрыт» выше не являются текущим разрешением на production.
